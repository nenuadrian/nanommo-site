    MMORPG game events with an event queue in C++

    An event queue for what happens in the world, from the C++ server's tick through the interest management to each player near it, over TCP, shown in the raylib client as combat text.

    Watch on YouTube

    We give our MMORPG game events, sent from the C++ server to the clients: an event queue, as Robert Nystrom's Game Programming Patterns calls it, where the world records what happens, and the server decides who reads it. The world records each hit, each blow taken and the health given back as events, next to the kills, levels and the rest it records for the analytics, which leave them out. The protocol gets an event message, and each tick the server sends each player the events near them, in their copy of the land, through the interest management's cells, over TCP so that none are lost, while the world's state goes on over UDP. The client keeps the events apart from the world it draws, and shows each as combat text: the damage over the monster, what it does back in red, healing in green, and a new level in gold. Along the way, a dead monster loses its nameplate, and the bots stop swinging at a body. This is episode 49 of a series about building an MMORPG from scratch in C++, with the focus on the engineering around the game.
