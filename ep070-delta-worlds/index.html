    Sending only what changed in a C++ MMORPG

    Our C++ MMORPG's server remembers a second of what it sent each client and leaves out of each world whoever hasn't changed since a world the client has whole, which roughly halves what forty bots receive.

    Watch on YouTube

    Delta compression for our MMORPG's worlds, in C++. Each world from the server carried everyone near you in full, twenty times a second, so a player standing in a crowd cost as much as one walking through it. Each input now says the newest world the client has whole, the server remembers a second of what it sent each client as a hash of each player's and monster's piece, and anyone who hasn't changed since goes by their id alone, which the client keeps as it has them. The bots send their keys each tick, through a queue of writes, so they say which world they have often enough to help. With forty bots on one machine, measured from the server's Prometheus metrics, each gets roughly half the bytes it did. This is episode 70 of a series about building an MMORPG from scratch in C++, with the focus on the engineering around the game.
