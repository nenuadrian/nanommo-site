    One sword, two servers

    Our C++ MMORPG's red-team client plays one character on two instances of a world and keeps a sword it traded away, until each character has a lease in Redis, saves are fenced by the lease's number, each sword has a serial and each trade a record.

    Watch on YouTube

    How an MMORPG keeps a character on one game server at a time, in C++ with Redis. Our red-team client plays one character on both instances of a world, as a deploy runs them, trades its sword away on one, and the other saves its bag from before the trade, so two swords become three. Now each character has a lease in Redis, taken as they say hello, renewed each second and handed over in a deploy, with Lua scripts so that nothing runs in between. Each lease has a fencing number, and each save checks it, so a server that stalls for longer than a lease, which we show with SIGSTOP, can't save over the one that took its player. Each sword gets a serial, each trade a record in MySQL, and Prometheus alerts on an item held twice. This is episode 79 of a series about building an MMORPG from scratch in C++, with the focus on the engineering around the game.
