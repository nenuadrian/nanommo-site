    Making an indie MMO resilient when Redis and MySQL fail

    Timeouts, failing fast, a saver that keeps its batch and trades that are called off, then we break our indie MMO again with the same chaos experiments and write our first postmortem.

    Watch on YouTube

    Making our indie MMORPG resilient when Redis and MySQL fail, after last episode's chaos experiments found a world that froze with Redis while our tick indicator said all was well, a saver that lost its batch, and a trade that copied a sword. Redis and MySQL get timeouts, and after one, neither is asked again for a moment, which is failing fast; a world that stalls lets the ticks it missed go, so the tick SLO can see it. The saver keeps each batch in Redis until MySQL has it, a trade Redis can't save is called off, and a login gives up after five seconds, with the bots counting their logins from outside, as black-box monitoring. Then we break it all again with the same experiments, compare before and after, and write our first blameless postmortem, after Google's SRE book, with what's still open. This is episode 89 of a series about building an MMORPG from scratch in C++, with the focus on the engineering around the game.
