    Prometheus and Grafana for a C++ game server

    Our server reports metrics, Prometheus collects them, Grafana draws them, Docker Compose starts it all, and three hundred bots give it something to show.

    Watch on YouTube

    We add metrics to our C++ game server with prometheus-cpp, and write bots that play like someone at the keys. Docker Compose runs the server, Prometheus and Grafana together, with the dashboard set up from files in the repo, and with three hundred bots online we see the bytes we send grow much faster than the players. This is episode 4 of a series about building an MMORPG from scratch in C++, with the focus on the engineering around the game.

    Why metrics

    2:01 So far, all we know about a running server is what it prints. Logs tell us about single events, such as player seven joining. However, they don't tell us how the server is doing overall. We'd like to know whether each tick finishes well within its fifty milliseconds, or gets close to the limit. We'd also like to see how many players are online compared with an hour ago, and how many bytes a second we send to all the clients together. Those are numbers that change over time, and that's what metrics are for. In production, they're how you find out that something's wrong, often before the players tell you. And once we start optimising, they're how we tell whether a change actually helped.

    2:42 Prometheus works by pulling the numbers from our server, instead of waiting for the server to push them. The server serves its current numbers over HTTP, at slash metrics, as plain text. At a regular interval, two seconds apart for us, Prometheus fetches that page, which is called a scrape. It stores each number with the time it read it, and a number with its history like that is called a time series. Grafana then asks Prometheus questions in PromQL, which is Prometheus's query language, such as the bytes sent per second over the last five minutes, and draws the answers. Pulling keeps the server simple, as it doesn't need to know where Prometheus is, or whether it's up.

    3:22 Prometheus is an open-source monitoring and alerting toolkit, which started at SoundCloud in 2012. It's now a project of the Cloud Native Computing Foundation, which also looks after Kubernetes. Its architecture has more pieces than we need today, such as the Alertmanager, which sends alerts when a number crosses a line, and service discovery, which finds what to scrape. For now, we use the Prometheus server in the middle, which scrapes and stores the time series, and Grafana, at the bottom right, to look at them.

    3:50 Prometheus has a few types of metric, and we're going to use three of them. A gauge is a number that goes up and down, such as the players online. A counter is a total that goes up, such as the bytes we've sent since the server started, and it's reset to zero when the server restarts. On its own, the total isn't very interesting, as it keeps going up for as long as the server runs. However, Prometheus can work out how fast it grows, which gives us bytes per second. And a counter doesn't miss anything that happens between two scrapes, while a gauge of bytes per second would. A histogram is for durations, such as how long each tick takes. With twenty ticks a second, there are forty of them between two scrapes. So the histogram counts them into buckets: how many took up to a tenth of a millisecond, how many up to a quarter, and so on. From the buckets, Prometheus estimates percentiles, such as the fiftieth percentile, or p50, which is the typical tick. The ninety-ninth, or p99, is the time that ninety-nine ticks in a hundred stay under. An average would hide a few slow ticks among a lot of fast ones, while the p99 shows them.
