    Trying to cheat in my own C++ MMORPG

    A red-team client for our C++ MMORPG breaks the client's rules one at a time, finds that the server already stops most of them, finds one that hits about twice as often, and the server gets its fix in this episode.

That way, a cheat it finds is fixed before anyone can read the code for it, which is the part I'd defend hardest. The obvious alternative is anti-cheat in the client, as most other games ship, though no episode weighed it. It runs on a machine the player controls, so it can be patched out, and to work, it has to watch the player's computer, which I'm not keen on either. The other is trusting the client and catching cheaters afterwards, from the logs, once the damage is done. What it costs us is a check on the server for each new kind of input, and a check the client also does, such as a cooldown it shows, is done twice. It goes in the index too, as the twenty-fifth row.

    Wrap-up

    31:42 Today, we wrote the server's red-team client, a player without a window that breaks the client's rules one at a time and prints what it gets for it. More inputs than ticks, a direction that's too long or not a number, a swing from twenty metres and a skill ten times a tick all got nothing a rule-keeping client doesn't. Putting the sword in the bag as each blow landed got about twice the hits, so now a skill keeps the effect it started with, and a swing whose blow has landed plays out.
