    Self-hosted GitHub Actions runner: deploy on push

    A GitHub Actions runner on our server, in Docker, deploys each push to main once CI passes, with the worlds handing their players over, and refuses any other job.

    Watch on YouTube

    We have our VPS deploy each push to main on its own, once CI passes, with a self-hosted GitHub Actions runner in Docker. The runner reaches the server's Docker through its socket, works in the deploying user's home folder at the path it has on the server, and starts each release through the worlds' next instances, so the players play on. As our repository is public, the runner refuses any job but a deploy of main.
