    Versioning a C++ MMO and updating its libraries

    Our C++ MMORPG gets a version, which the client shows and the login server checks, and its libraries get pinned by hash and updated each week.

    Watch on YouTube

    Our MMORPG gets a version, set once in CMake for the C++ client and all the servers: the client shows it in the corner of its login screen, the servers print it as they start, and Prometheus gets it as a build info metric. The login server checks each client's version and turns away one that doesn't speak its protocol, saying which version to get. A Python script lists the C++ libraries FetchContent pins that have newer versions, moves them on and pins each by its SHA-256, and when raylib 6.2 breaks our tests with a double free, we see why updates go through CI. Dependabot and a GitHub Actions workflow open pull requests with the newest versions each week, and a changelog says what each version changed. This is episode 59 of a series about building an MMORPG from scratch in C++, with the focus on the engineering around the game.
