    nanoMMO

    The MMO I'd like to see exist, built from scratch in C++, with the engineering and the hard parts out in the open.

    nanoMMO is a devlog where I build an MMO from scratch in C++, with features I'd like to see exist, even if some might be impractical for most games, such as players creating their own skills. It's a learning journey, with the software engineering and the hard parts out in the open, and not always about the gameplay.

    The name is a working title. It takes after nanochat, a repository by Andrej Karpathy, with code that's kept minimal and easy to hack on. That's what I'm going for here as well: a codebase that covers an MMO from one end to the other, which you can read, run yourself, and play with.

    The episodes are on YouTube. The game's code is on GitHub, tagged at each step of each episode, so you can follow along. Its API docs are here, and the reasons it's built the way it is are in its decision records.

    Design choices

    Each choice that shaped the game is a decision record in its repository, with what was decided, what else was weighed and what it costs. 40 so far, and 38 of them still stand.

    1. 0040Check the content as a graph, with smollerGraph, in the tests
    2. 0039Objectives with error budgets, and chaos experiments in staging, never in production
    3. 0038Trace requests with a tracer of our own, which speaks OpenTelemetry
    4. 0037The server owns the sky
    5. 0036A boss fights whoever's hurt it most, and its death is everyone's who took 5% of its health
    6. 0035A monster's skill lands where it was aimed, after a telegraph players can step out of
    7. 0034Duel blows are checked where the attacker saw the target, up to 200 milliseconds back
    8. 0033Players fight each other in duels, which end at one healthLv 81
    9. 0032A browser reaches the servers through a WebSocket gateway
    10. 0031A character is leased to one instance at a time
    11. 0030Offline, the client runs the world's rules itselfLv 78
