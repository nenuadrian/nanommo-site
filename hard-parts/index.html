    The hard parts

    Quite a few things have broken along the way in nanoMMO, and some were genuinely hard to get right. Here they are, a sentence or two each, with the episode where it happens and the code at the end of it, if you'd like to try it yourself.

    Keeping up with the players

    • Episode 8Profiling a C++ game server with perf and Tracy

      Past a thousand bots, the server fell behind its tick. Profiling it with perf and Tracy pointed at the broadcast, which serialised the whole world for each client, so now it's serialised once a tick, and the server keeps up with twice the players.

      The code at ep008/end
    • Episode 20MMO interest management to send each player less

      Sending each player the whole world grows with the square of the players. So the island goes into cells of 32 metres, and each player gets what's near them, measured on my machine and on the VPS.

      The code at ep020/end
    • Episode 46MMORPG server load test, with flame graphs from Pyroscope

      Against two thousand bots that take quests and hunt for them, the server kept its twenty ticks a second up to 1,300 players, and managed about eight at 2,000. Pyroscope's flame graph follows where the time went, from the broadcast down to the kernel's UDP stack.

      The code at ep046/end
    • Episode 70Sending only what changed in a C++ MMORPG

      Each world the server sent carried everyone near you in full, twenty times a second, so a player standing in a crowd cost as much as one walking through it. Now whoever hasn't changed since a world the client has whole goes by their id alone, which roughly halves what forty bots receive.

      The code at ep070/end

    Slow and lossy networks

    • Episode 9TCP vs UDP for a game server, under packet loss

      We dropped packets with netem and measured how old the world on a player's screen gets. Over TCP, head-of-line blocking made the worlds wait for each lost packet, so the world goes over UDP now, in parts that fit in a packet.

      The code at ep009/end
    • Episode 68Client-side prediction in a C++ MMORPG, on a slow network

      On a network slowed to a 150 ms round trip, your player started and stopped walking late, as each key went to the server and back. Now the client numbers its inputs and walks you at once, with the server's own walking code, and the server's answer corrects it.

      The code at ep068/end
    • Episode 69Smooth movement for other players in a C++ MMORPG

      On a network that loses packets, the other players and the monsters stopped and lurched whenever a world came late or not at all. The client now draws them a tenth of a second in the past, between two worlds it already has.

      The code at ep069/end

    Saving the players

    • Episode 13Redis cache in C++ with write-behind to MySQL

      Saving to MySQL after each tick fell behind at fifty players. Redis went in between, written in a single round trip each tick, with a saver of our own writing behind to MySQL, and when we crash the server, the players come back where they were.

      The code at ep013/end
    • Episode 18MySQL schema migrations with Flyway in Docker

      Changing a table meant deleting the database, and the players' accounts with it. Flyway keeps the tables in versioned migrations now, and when we edited the first one, it failed its checksum, so the change went into a second migration instead.

      The code at ep018/end
    • Episode 67MMORPG guild ranks in C++ with a roster, officers and kicks

      A kick and a leave can arrive at the same moment from two instances of a world. Each change locks the guild's row first and then the player's, with SELECT ... FOR UPDATE, so the two go one after the other without a deadlock, and a test runs them on two MySQL connections.

      The code at ep067/end

    Cheats, dupes and plain text

    • Episode 14TLS for a C++ game server with OpenSSL and Asio

      With tcpdump, we watched passwords and login tokens cross the network as plain text. Each TCP connection gets TLS 1.3 now, through OpenSSL and Asio, with a certificate authority of our own.

      The code at ep014/end
    • Episode 72Trying to cheat in my own C++ MMORPG

      We wrote a client that breaks the rules on purpose, and the server already stopped most of what it tried. Putting the sword in the bag as each blow landed, and back a moment later, cut the swing short for about twice the hits, so a skill now keeps the timings of the weapon it started with.

      The code at ep072/end
    • Episode 75How MMO item dupes happen

      Our red-team client found two dupes in the simple trading of the episode before: moving an offered sword to another slot, and leaving right after saying it's ready, before the next tick saved the bags. Now the server holds what's offered where it is, checks it before it gives anything, and saves both players of a trade at once, in one Redis transaction.

      The code at ep075/end

    Tests, tools and CI

    • Episode 28C++ sanitizers, fuzzing and coverage in Docker

      Sanitizers under two hundred bots, a fuzzer, clang-tidy and a coverage report found what our tests didn't: a leak in raylib, a data race in our metrics' web server, and stories the storyteller would lose. We fixed what they found, in Docker and in CI.

      The code at ep028/end
    • Episode 29Integration testing a C++ game server

      Our first test that starts a whole world server passed in a release build, and UBSan stopped it as it was torn down: the test destroyed its I/O context before the server that still used it. Declaring the context first fixes the order.

      The code at ep029/end
    • Episode 34MMORPG skill trainer NPC with MySQL and Redis

      CI had been failing since episode 28, for a few reasons at once, from coverage pages GitHub's runner couldn't read to a generated header clang-tidy's stage didn't have. The episode fixes them before it adds the trainer.

      The code at ep034/end
    • Episode 59Versioning a C++ MMO and updating its libraries

      When a script moved our libraries on to their newest versions, raylib 6.2 broke our tests with a double free. That's why updates go through CI, as pull requests that Dependabot and a workflow open each week.

      The code at ep059/end

    Deploying and running it

    • Episode 30Prometheus Alertmanager alert rules and email

      A world that crashed dropped out of Consul, and its alert let go along with it. So we wrote a rule that holds on, and promtool tests the rules in CI.

      The code at ep030/end
    • Episode 36Zero downtime deploys for an MMORPG game server

      A deploy used to throw everyone out. Now a world hands its players over to its next instance through Consul before it stops, and each move needs a fresh token, as we found out when a reused one sent alice back to the login screen.

      The code at ep036/end
    • Episode 65From git clone to playing a C++ MMORPG

      Following our own README on a brand-new Ubuntu machine, quite a lot got in the way, from six hundred build warnings to Redis and MySQL published to the network. Each one is fixed in the code, and a doctor script checks the machine and prints one command that installs what's missing.

      The code at ep065/end

    In the browser, and on screen

    • Episode 76Running my C++ MMORPG in a web browser with WebAssembly

      On its way into a browser tab, the client was stopped by three things a browser does differently: a loop that never handed the browser its turn, shaders in desktop GLSL that WebGL 2 won't take, and reading a texture back in a format WebGL doesn't have. After those, the login screen draws in a tab.

      The code at ep076/end
    • Episode 78Playing my C++ MMORPG offline in a browser, without a server

      In the browser, tall spindles stood by each person. It came down to raylib sending WebGL its bone matrices untransposed, and a patch fixes it.

      The code at ep078/end
    • Episode 86Weather effects and ambient sound in a C++ MMORPG

      The rain we made from numbers sounded like glass beads. So the rain and the fire are recordings now, kept out of git.

      The code at ep086/end
